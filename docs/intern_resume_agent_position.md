## 项目经历

### Paper Research Agent：多工具论文调研 Agent

**项目角色**：独立开发  
**技术栈**：Python、arXiv API、Semantic Scholar API、OpenAlex API、DeepSeek API、PyMuPDF、JSON、Markdown、CLI、`.env`  
**项目地址**：[填写 GitHub 仓库链接]  

#### 项目简介

独立设计并实现一个面向学术论文调研的 Tool-Using Agent。用户输入研究主题后，系统自动调用多个真实论文源检索论文，融合多源元数据，尝试下载和解析 PDF，抽取证据片段，并生成可追溯的 Markdown 综述报告；同时支持 DeepSeek API 作为 LLM 写作增强模块。

#### 核心工作

- **设计端到端 Agent 工作流**：实现从研究主题输入到论文检索、元数据保存、PDF 下载、文本解析、证据抽取、综述生成和结果评测的完整流程。
- **接入多源论文检索工具**：集成 arXiv、Semantic Scholar、OpenAlex 三类真实论文数据源，解决单一 arXiv API 易限流、超时和不可用的问题。
- **统一论文数据模型**：设计 `Paper` 数据结构，统一封装标题、作者、摘要、PDF 地址、来源、引用数等字段，并支持多源结果去重与融合。
- **实现工具失败降级策略**：针对 arXiv `429 Too Many Requests`、`503 Service Unavailable`、网络超时、PDF 下载失败等问题，实现请求等待、重试、缓存、多源切换和摘要兜底。
- **构建证据驱动生成链路**：先生成 `papers.json` 与 `evidence.json`，再将结构化论文和证据输入 DeepSeek，约束模型基于证据生成综述，降低无依据生成和幻觉风险。
- **支持多种运行方式**：实现命令行参数模式和 VSCode 直接运行交互模式，用户可以选择论文检索源、论文数量、证据数量和写作方式。
- **完善隐私与配置管理**：使用 `.env` 保存 DeepSeek、Semantic Scholar、OpenAlex 等 API Key，并通过 `.gitignore` 避免敏感信息提交到 GitHub。
- **输出可追溯产物**：生成 `papers.json`、`evidence.json`、`report.md`，便于检查论文来源、证据片段和最终综述内容。

#### 项目亮点

- 相比普通问答应用，本项目具备 Agent 特征：多工具调用、多步骤执行、状态落盘、异常恢复和结果评测。
- 相比单一 API 脚本，本项目支持 arXiv / Semantic Scholar / OpenAlex 多源真实检索，提高论文覆盖率和系统鲁棒性。
- 相比直接调用大模型生成，本项目采用 evidence-first 设计，先检索真实论文与证据，再让 DeepSeek 基于证据写作。
- 项目包含详细工程文档，包括 README、逐行代码解释、开发过程复盘、简历与面试准备指南，体现了工程交付能力。

#### 可量化结果

- 支持 **3 类真实论文源**：arXiv、Semantic Scholar、OpenAlex。
- 支持 **2 种报告生成模式**：规则式生成、DeepSeek LLM 生成。
- 支持 **2 种运行方式**：CLI 命令行运行、VSCode 交互式运行。
- 输出 **3 类核心产物**：`papers.json`、`evidence.json`、`report.md`。
- 处理 **5 类常见异常**：API 限流、服务不可用、网络超时、PDF 下载失败、API Key 缺失。
